# 操作ガイド

画面左側にサーバー一覧と用途別のページがあります。[画面とデータの扱い](UI_AND_BACKUP.md)と[日本語設定と画面の場所](JAPANESE_SETTINGS.md)を参照してください。

通常は[インストーラー版](INSTALLATION.md)を利用してください。インストール後はスタートメニューから起動できます。既存のDocuments内のデータをそのまま使用します。


## 表示設定（v0.1.1）

左下の「アプリ設定」から表示ページを開き、ダーク／ライトを選びます。画面・入力欄・選択リスト・アプリ内確認ダイアログへ即時反映し、`data/settings.json` に保存します。サーバー再起動は不要です。Windowsのファイル・フォルダ選択画面はOSのテーマに従います。

「種類とバージョン」のFabricローダーバージョン欄はFabric選択時だけ表示します。Vanillaなど別の種類で保存した場合、Fabric指定は解除します。Minecraft候補一覧は選択中の種類に合わせて取得し、Forge / NeoForge / Quilt / customでは導入済み環境のバージョンを手入力してください。

## 1. インストール

Windows x64用ZIPを展開してください。portableは.NET 10 Desktop Runtime x64を使う小型版、standaloneは.NET込みの版です。JavaはMinecraftのために別途必要で、アプリ自身の実行には使いません。ZIP内のDLL・設定ファイルも一緒に保存します。起動ファイルは `CraftHarbor.exe` です。

## 2. サーバープロファイル

「サーバーを追加」で専用フォルダが作られます。表示名と実体フォルダIDは別です。名前変更でワールドの場所は変わりません。サーバーの自動起動はしません。

「種類とバージョン」で種類・Minecraftバージョン、「Java・メモリ・ポート」でJavaパス・メモリ・ポート、「起動引数」でJARパスと追加引数を設定します。各ページで保存してください。稼働中は保存できません。

標準の起動方法は以下です。実際にはシェルを使わず引数配列で渡します。

```text
java.exe -Xms512M -Xmx2048M [追加JVM引数] -jar server.jar nogui
```

JVM・カスタム引数は **1行に1引数**。空白のある値も引用符で囲まず入力します。追加JVM引数に別の `-Xmx` を指定せず、メモリ欄で指定してください。

サーバーポートは「Java・メモリ・ポート」の設定を正として、起動時に `server.properties` へ反映します。複数サーバーは別ポートにしてください。初期値25565が既存サーバーに使われていれば起動を拒否します。

## 3. サーバー本体とJava

Vanilla / Paper / Fabric / Foliaは「本体の導入」ページで取得できます。Paper / Foliaでは安定ビルドだけを選びます。安定ビルドがなければエラーを出し、別バージョンへの自動変更はしません。Fabricは空欄で最新安定ローダー、指定があればそのローダーを取得します。

本体導入時にMojangのメタデータからJava要件を表示します。PaperやMODパックに追加要件がある場合は作者の文書を確認してください。

Java画面はTemurin JREを `data/java` に展開します。システムの `PATH` や `JAVA_HOME` は書き換えません。Java一覧で選んで「選択サーバーに割り当て」を押します。独自JDKも `java.exe` の選択で利用できます。

## 4. EULAと接続

Minecraft EULAの同意は利用者が行います。アプリは未同意のプロファイルを起動しません。同意済みの起動時に専用フォルダへ `eula=true` を保存します。作成直後は `online-mode=true` を使用します。

同じPCからは `localhost:ポート`、LANからはシステム画面に出るLAN IPとポートへ接続します。インターネット公開は運用ガイドを参照してください。

## 5. コンソールと停止

選択したサーバーの標準出力・標準エラーを表示します。画面上限は2,000行、長すぎる1行は8,192文字で分割します。出力は `data/logs/<id>` に保存します。コマンド先頭の `/` は省略でき、入力欄では改行を許可しません。

「安全に停止」は標準入力へ `stop` を送り、最大60秒待ちます。時間切れでも勝手に強制終了しません。ログを確認して待つか、明示的に強制終了を選べます。再起動は停止完了後のみです。アプリから起動したサーバーが残っている間は通常のウィンドウ終了を止めます。

プロキシなど `stop` が停止コマンドでない実装は、カスタムJARとして起動可能でも「安全に停止」ボタンと互換ではありません。本版の正式対象はMinecraft Javaサーバーです。

## 6. MOD・プラグイン

ローカルのJARをmodsまたはpluginsに追加できます。有効・無効は `.jar` と `.jar.disabled` の名前切替です。稼働中の変更はできません。同名のファイルは上書きしません。

Modrinth検索はプロファイルのMinecraftバージョンとローダーで絞り込みます。Paper / Foliaではプラグインを検索してpluginsへ、MODローダーではmodsへ導入します。検索結果から導入すると必須依存を解決し、一覧を表示します。確認後にダウンロード・SHA512検証し、取得が全て成功してから配置します。既存MODの別バージョンは自動削除しません。重複・競合は利用者が確認してください。

## 7. MODパック

新しい空サーバーを作り、**本体を入れる前に** `.mrpack` を取り込みます。対応はModrinth CDNにある必須サーバーファイルと、`overrides` / `server-overrides` です。クライアント専用と任意サーバーファイルは省きます。未知の配布元や配置先は処理を止めます。

パックのMinecraftバージョンとローダー種別を反映し、Fabricの指定版も保存します。その後、「本体の導入」でサーバー本体を導入してください。Forge / NeoForge等はパック作者の指示でローダーを導入したフォルダを使います。CurseForge形式のmanifest自動解決はありません。

## 8. プリセット・設定ファイル

プリセットはMOD・プラグインJARと、config / defaultconfigs / kubejs / scripts / 各ワールド直下のserverconfig / プラグインの対応テキスト設定 / AutoModpackのサーバー設定を保存します。ワールド本体、起動プロファイル、Java、server.propertiesは含みません。標準では現在の設定を維持し、未配置の設定だけ追加します。「現在の設定を維持」のチェックを外すと同名設定を復元します。どちらもプリセットにない設定は削除しません。切替前に全体バックアップを作り、失敗時は復旧します。[範囲と制限](MOD_CONFIGURATIONS.md)。

設定ファイル画面はサーバー直下・プリセット対象の設定場所・pluginsから対応拡張子を最大500件、1ファイル1MB未満まで表示します。JSONは構文チェックを行います。その他の形式の意味的な妥当性は検証しません。保存はUTF-8で、旧ファイルをfile-historyへ残します。未保存の設定ファイル編集には移動時の確認があります。各設定フォームは別ページへ移動する前に保存してください。

Paperの既存ワールドでは、server.propertiesのdifficultyだけを編集しても難易度が変わらない場合があります。コンソールへ `difficulty hard` などを送信して変更し、`difficulty` で確認してください。1.21.1 build 133の実検証でもこの挙動を確認しています。起動設定のポートはserver.propertiesより優先します。

Javaのリダイレクト入出力をUTF-8で揃えているため、日本語のコマンドやログを扱えます。Java 21の実サーバーで検証しています。
